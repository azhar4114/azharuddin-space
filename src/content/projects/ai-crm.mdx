## 1. Overview

**AI CRM** is a modern, full-stack customer relationship management prototype engineered to explore clean architectural patterns, robust API design, and pragmatic AI integration.

The application pairs a high-performance **Python FastAPI** backend with a responsive **React + TypeScript** frontend, automating contact record ingestion, communication logging, and AI-driven contact summarization using modern Large Language Model (LLM) APIs.

---

## 2. Problem or Motivation

Traditional CRM systems often suffer from significant operational drawbacks for small teams:
- **Cumbersome Manual Logging:** Sales and operations professionals spend disproportionate time summarizing meeting notes, email threads, and contact updates.
- **Provider Lock-In:** Most AI-enabled tools lock users into a single model vendor (e.g., proprietary OpenAI endpoints), creating vulnerabilities to vendor pricing hikes, rate limits, or outages.
- **Brittle Data Import Pipelines:** Ingesting messy CSV and Excel files frequently crashes application backends due to lack of schema validation.

---

## 3. Project Objectives

- Design a decoupled, maintainable backend architecture adhering to Clean Architecture principles.
- Implement a vendor-agnostic AI service layer supporting seamless runtime switching between Google Gemini, OpenAI, Groq, and OpenRouter.
- Build a resilient bulk-import pipeline capable of sanitizing and validating Excel (`.xlsx`) and CSV files before database insertion.
- Deliver an accessible, fast frontend UI featuring real-time client-side search, filtering, and modal editing.

## 6. Technical Implementation

### A. Decoupled Clean Architecture Backend
- **Domain Layer:** Pure data structures and validation schemas defined using Pydantic (`ContactSchema`, `ContactCreate`, `InteractionCreate`).
- **Infrastructure Layer:** Database session management via SQLAlchemy ORM with automated table initialization on boot.
- **Use Cases Layer:** Business logic encapsulated in dedicated services, isolating external third-party API clients from HTTP controllers.

### B. Multi-Provider LLM Intelligence Engine
- Unified client abstraction that standardizes model requests and response formats across **Google Gemini**, **OpenAI**, and **OpenRouter**.
- Generates concise interaction summaries, extracts key relationship milestones, and suggests automated next-best actions from unstructured text notes.

### C. Bulk Ingestion Pipeline
- Engineered multipart upload endpoints supporting streaming CSV and native Excel (`.xlsx`) ingestion using `openpyxl`.
- Implements strict field-level validation (sanitizing telephone numbers, normalizing email addresses, and stripping malicious script injections).

### D. Single-Page Application Frontend
- Built with React 18, Vite, TypeScript, and Tailwind CSS.
- Features responsive data tables with zero-latency client-side filtering, debounced search, and inline modal state management.

---

## 7. Key Engineering Decisions

- **FastAPI over Django/Flask:** Selected FastAPI for its native async support, automated OpenAPI (Swagger) documentation, and high-performance serialization via Pydantic.
- **SQLite for Prototype Persistence:** Utilized SQLite via SQLAlchemy for zero-configuration, lightweight local deployment, designed with repository abstractions to allow seamless drop-in replacement with PostgreSQL.
- **Unified Local Orchestration:** Created a single `./start.sh` startup script managing concurrent backend (`uvicorn`) and frontend (`vite`) processes with proper Unix signal trap handlers.

---

## 8. Challenges and Solutions

| Challenge | Engineering Solution |
|---|---|
| **LLM Provider Rate Limits & Variance** | Implemented a unified provider adapter that normalizes payload structures and allows switching model providers via configuration without modifying business logic. |
| **Excel Format Inconsistencies** | Implemented openpyxl cell-type inspection to handle mixed numeric/text telephone numbers and date formatting anomalies gracefully. |
| **Concurrent Process Lifecycle in Dev** | Wrote a robust Bash wrapper script with `trap 'kill 0' SIGINT SIGTERM` to cleanly terminate both Uvicorn and Vite servers on exit. |
