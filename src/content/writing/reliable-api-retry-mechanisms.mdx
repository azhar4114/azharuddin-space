## Introduction

Retry logic is one of those things that seems simple at first — just try again if it fails — but gets complicated quickly when you think about what can go wrong. Done poorly, retries amplify failures rather than recover from them.

This article covers the key ideas behind building retry mechanisms that are genuinely reliable: idempotency, exponential backoff with jitter, and the observability you need to know whether your retry strategy is working.

## Idempotency

A retry is only safe if the operation being retried is idempotent — meaning repeating it produces the same result as running it once. Getting this wrong means retries can cause duplicate data, duplicate charges or repeated side effects.

## Exponential backoff with jitter

```python
import random
import time

def retry_with_backoff(fn, max_attempts=5, base_delay=1.0, max_delay=60.0):
    """
    Retry fn with exponential backoff and full jitter.
    """
    for attempt in range(max_attempts):
        try:
            return fn()
        except Exception as e:
            if attempt == max_attempts - 1:
                raise
            delay = min(max_delay, base_delay * (2 ** attempt))
            jittered = random.uniform(0, delay)
            time.sleep(jittered)
```
